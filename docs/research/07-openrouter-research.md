## Executive Summary (5 Key Findings)

1. **Edition detection matters for automation:**
   - OpenLiteSpeed (OLS): Plain-text `/usr/local/lsws/conf/httpd_config.conf` with `block { key value }` grammar — trivially scriptable via sed/awk/Python + `include` files for isolation.
   - LiteSpeed Enterprise (LSWS): XML config + native Apache directive reading → automate via Apache include files (e.g., `/etc/apache2/conf.d/includes/pre_main_global.conf`) and `.htaccess`, not the XML itself.

2. **PHP process sizing is the real lever (ProcessGroup mode):**
   - `maxConns` must equal `PHP_LSAPI_CHILDREN` (both OLS and LSWS).
   - Formula: `CHILDREN ≈ (free_RAM − 300M) / per_lsphp_RSS` (30–150 MB for WordPress/WooCommerce).
   - Critical tuning: `LSAPI_AVOID_FORK=200M` (keep children alive only if ≥200M free), `LSAPI_MAX_REQS=1000–10000` (recycle), `LSAPI_MAX_IDLE=60–3600` per tier.
   - **Pitfall:** bare `LSAPI_AVOID_FORK=1` requires ≥1 GB free RAM or silently behaves like `LSAPI_AVOID_FORK=0`.

3. **Server LSCache configuration (never force-enable globally):**
   - **Wrong:** `enableCache 1` server-wide = all responses cached, WooCommerce cart poisoned, PHP never runs.
   - **Right:** `ignoreRespCacheCtrl 0` (obey app headers) + let LSCWP plugin drive caching via `X-LiteSpeed-Cache-Control` headers.
   - **OLS:** `module cache { storagePath $VH_ROOT/lscache; ... }` per vhost (separate storage).
   - **LSWS:** `CacheRoot /home/lscache/` server-level + `CacheEngine on esi crawler` (ESI = Enterprise-only hole-punching for WooCommerce cart/checkout).

4. **Anti-DDoS / per-client throttling baselines:**
   - WordPress-safe: `dynReqPerSec 2, staticReqPerSec 40, softLimit 15, hardLimit 20, blockBadReq 1`.
   - `WordPressProtect drop,10` (Enterprise only); OLS lacks it — use ModSec or fail2ban.
   - HTTP/3 (QUIC) on by default but requires UDP 443 open + CSF `UDPFLOOD=0` (or iptables equivalent).

5. **RAM-tier reference table captured:**
   - 1 GB: 10–15 children, AVOID_FORK=0, memory_limit=128–256M, OPcache=64M.
   - 2 GB: 20–35 children, AVOID_FORK=0, memory_limit=256M, OPcache=128M.
   - 4 GB: 35–60 children, AVOID_FORK=500M, memory_limit=256–512M, OPcache=192M.
   - 8+ GB: 60–100+ children, AVOID_FORK=1, memory_limit=512M, OPcache=256M.

## How to Use This Research

### For a Bash CLI Optimizer Script

1. **Detect Edition:**
   ```bash
   [ -f /usr/local/lsws/conf/httpd_config.xml ] && EDITION=LSWS || EDITION=OLS
   ```

2. **Measure & Calculate:**
   - Read `/proc/cpuinfo` (core count), `/proc/meminfo` (free RAM).
   - Sample `ps -ylC lsphp --sort:rss` to estimate per-child RSS.
   - Compute `CHILDREN = (free_RAM − 300) / per_child_RSS`.

3. **Read Configuration:**
   - OLS: Parse `/usr/local/lsws/conf/httpd_config.conf` (line-oriented, support `include`).
   - LSWS: Read `.htaccess` / Apache includes; avoid scripting the XML.

4. **Apply Changes:**
   - OLS: Write to a new file in `/usr/local/lsws/conf/includes/` (auto-included) or edit main config with sed.
   - LSWS: Write Apache-style directives to `/etc/apache2/conf.d/includes/pre_main_global.conf` (cPanel).
   - Both: Validate syntax (`lswsctrl status` or Apache `apachectl configtest`).
   - Apply: `lswsctrl restart` (graceful; existing requests finish).

5. **Verify:**
   - WebAdmin Real-Time Stats: `https://localhost:7080` → External App → check **WaitQ** (should be 0).
   - Check cache hits: `curl -I https://site/page/ | grep X-LiteSpeed-Cache`.
   - HTTP/3: `curl --http3 -I https://site/`.

## Notes & Caveats

- **OLS vs LSWS automation:** OLS is script-friendly (plain text + includes); LSWS is best automated via Apache includes/.htaccess, not XML parsing.
- **Cache poisoning risk:** Always pair LSCache with LSCWP or equivalent cache-driver logic that understands WooCommerce cart/checkout (set `ignoreRespCacheCtrl 0` + require `X-LiteSpeed-Cache-Control` headers).
- **AVOID_FORK memory threshold:** OLS ships `LSAPI_AVOID_FORK=200M` by default; Enterprise often uses bare `1`. Know the difference: bare `1` fails silently if <1 GB free.
- **HTTP/3 firewall:** Not just "open UDP 443" — CSF firewall requires `UDPFLOOD=0` or QUIC traffic is rate-limited to 10 pps.
- **WooCommerce ESI (Enterprise only):** Dynamic cart/checkout content is injected by LiteSpeed if `CacheEngine on esi` is set; on OLS, cart pages simply never cache (correct default behavior, no plugin tweak needed).
